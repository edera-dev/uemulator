# Wisp Internet for Web Guests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Web guests reach TCP and UDP hosts (so `apk update` and `apk add` work) through a Wisp server, using one user-mode gateway in the library that the CLI shares.

**Architecture:** usernet's protocol engine moves into the library as a sans-I/O `Gateway` (frames in and out, stream requests out, stream events in, time passed as milliseconds). The CLI drives it with host sockets; the web worker drives it with a library `WispClient` whose WebSocket lives on the page and reaches the worker through a never-dropping shared ring. The segment's DHCP starts handing out 10.0.2.2 as router and DNS.

**Tech Stack:** Rust (`no_std` + `alloc` library, wasm32 web crate), JavaScript (page and worker, Node 26 for scripts), Python 3 stdlib (`serve.py`).

**Spec:** `docs/plans/27-wisp.md`

## Global Constraints

- The library is `no_std` + `alloc` under `cfg(freestanding)` (`use crate::prelude::*`), has no third-party dependency without `jit`, never touches stdio, never panics on guest or server input, holds no global mutable state, reads no clock (every time-dependent call takes `now_ms: u64`).
- `lib.rs` is the whole public API; new types are exported there and everything else is `pub(crate)`.
- No magic constants: protocol numbers, offsets, sizes and timeouts are named `const`s at the narrowest scope.
- Comments per `CLAUDE.md`: only what is surprising, terse, for the next maintainer.
- Before every commit: `./hack/autofix.sh`, then fix by hand anything left; `cargo clippy --release --all-targets` and `cargo clippy --release --target wasm32-unknown-unknown -p uemulator-web` print zero warnings.
- Fixing a bug: failing test first. Unit tests use no network and nothing under `~/.uemulator`.
- CLI bulk TCP must stay within noise of 652 MB/s down and 748 MB/s up (`ubench net`, `docs/plans/23-guest-io-perf.md` round 2).
- Wisp stream bytes are never dropped or reordered anywhere between the WebSocket and the gateway; Ethernet frames may be.
- Wisp v1 only (`MercuryWorkshop/wisp-protocol` `protocol.md`); packet type 5 is ignored.
- Constants fixed here: default resolver `1.1.1.1:53`; `WISP_DATA_MAX` 16384 bytes per DATA payload; reconnect backoff 1 s doubling to 30 s; Wisp handshake timeout (no initial CONTINUE) 10 s; wisp ring 1 MiB; largest wisp ring record 256 KiB.

## Review Focus

- A Wisp server sends DATA, CONTINUE or CLOSE for a stream the client never opened or already closed (v86 throws on this): ignored, nothing else disturbed. Test in Task 8.
- The WebSocket drops in the middle of a download: every open stream is reset to the guest, opens fail fast until it reconnects, and a new connection after reconnecting works. Tests in Task 8 (client) and Task 12 (end to end).
- The URL points at something that accepts the WebSocket but never sends the initial CONTINUE (a non-Wisp endpoint): queued opens fail after the 10 s handshake timeout instead of hanging the guest's connects forever. Test in Task 8.
- A burst of server data larger than the 1 MiB ring while the worker is busy: the page queues and nothing is lost. Test in Task 12 (an 8 MiB download compared by SHA-256).
- The server closes a stream (0x02) while the gateway still holds data the guest's window has not taken: the guest gets all the data, then the FIN. Test in Task 3.

### Task 3: Gateway TCP flows over streams

**Files:**
- Create: `crates/uemulator/src/gateway/tcp.rs`, `gateway/tests/tcp.rs`
- Modify: `gateway/mod.rs`
- Source: `usernet.rs` `tcp_in`, `send_reset`, `TcpFlow`, `poll_at`'s TCP half, `tcp_service_order`; tests from `usernet/tests.rs` `tcp`, `large_segments`, `robustness`.

**Interfaces:**
- Consumes: Task 2's request/event API.
- Produces (exported):
  - A guest SYN to a new flow yields `Open { kind: Tcp }`; `opened` sends the SYN-ACK; `failed` sends RST|ACK and drops the flow.
  - `impl Gateway { pub fn to_remote(&self, stream: StreamId) -> &[u8]; pub fn consumed(&mut self, stream: StreamId, bytes: usize); pub fn room(&self, stream: StreamId) -> usize; pub fn interest(&self) -> Vec<(StreamId, StreamInterest)> }`
  - `pub struct StreamInterest { pub read: bool, pub write: bool }` (`read`: `room > 0` and the guest queue is under its limit; `write`: `to_remote` is non-empty).
  - `to_remote` is the first contiguous run of guest bytes waiting (empty when none); the advertised window is 65535 minus all waiting bytes.
  - `room`: how many remote bytes the gateway will accept now for the stream (guest window minus in flight minus buffered, 0 for unknown streams). `remote_data` beyond `room` is still accepted and buffered (a Wisp server cannot be held back).
  - `poll(now_ms)` moves buffered remote data to the guest within its window and the per-poll frame budget (512 queued frames), round-robin, sends window updates, and emits `remote_closed`'s FIN only after the buffered data.
  - Guest FIN yields `ShutdownWrite` once `to_remote` is empty. Both directions done (guest FIN, remote closed, our FIN acknowledged) yields `Close`. Guest RST yields `Close` at once. `reset` sends RST|ACK to the guest and drops the flow without a `Close`.

**Interfaces:**

When the TCP stream fails too (no uplink at all), every query waiting on it gets ICMP port unreachable, so a guest without an uplink fails at once.

### Task 8: Wisp client driving the gateway

**Files:**
- Modify: `crates/uemulator/src/wisp/{mod.rs,tests.rs}`, `crates/uemulator/src/lib.rs` (exports)

**Interfaces:**
- Consumes: `Gateway` request/event API (Tasks 2-3), codec (Task 7).
- Produces (exported):
  - `pub enum WispState { Disconnected, Connecting, Ready }`
  - `pub struct WispStatus { pub state: WispState, pub last_close_reason: Option<u8> }`
  - `impl WispClient { pub fn new() -> WispClient; pub fn connecting(&mut self, now_ms: u64); pub fn connection_lost(&mut self, gateway: &mut Gateway); pub fn from_server(&mut self, message: &[u8], gateway: &mut Gateway); pub fn pump(&mut self, gateway: &mut Gateway, now_ms: u64); pub fn take_messages(&mut self) -> Vec<Vec<u8>>; pub fn status(&self) -> WispStatus }`
  - Behaviour: `connecting` (WebSocket created) enters `Connecting`; the CONTINUE on stream 0 enters `Ready` and sets every new stream's credit. In `Disconnected`, each `Open` request is answered with `gateway.failed`. In `Connecting`, opens wait; after 10 000 ms without the initial CONTINUE, waiting opens fail and the state is `Disconnected` (the page reconnects). In `Ready`: `Open` sends CONNECT (host as dotted decimal) and calls `gateway.opened` at once; TCP `to_remote` goes out as DATA of at most 16384 bytes while credit lasts, each followed by `consumed`; `Datagram` is one UDP DATA without credit; `ShutdownWrite` sends nothing; `Close` sends CLOSE 0x02 unless the server closed the stream already. From the server: DATA to `remote_data`, CONTINUE to credit, CLOSE 0x02 to `remote_closed`, any other CLOSE to `reset` (reason kept in `last_close_reason`); anything for an unknown stream id is ignored. `connection_lost` resets every live stream and enters `Disconnected`.

  - `nothing_is_sent_before_the_initial_continue` — an Open while `Connecting` produces no message until CONTINUE(0, 32) arrives, then exactly one CONNECT.
  - `opens_fail_at_once_when_disconnected` — a guest SYN with the client never `connecting` gets a RST.
  - `the_handshake_times_out_after_ten_seconds` — `connecting(0)`, guest SYN, `pump(9_999)` sends nothing and no RST; `pump(10_000)` RSTs the guest and `status().state == Disconnected`.
  - `the_syn_ack_goes_out_when_connect_is_sent` — after CONNECT the guest has a SYN-ACK without any server packet.
  - `data_waits_for_credit` — credit 2, 3 × 16384 bytes from the guest: two DATA packets, then none until CONTINUE(stream, 2).
  - `data_payloads_never_exceed_the_cap` — every DATA ≤ 16384 bytes.
  - `voluntary_close_is_a_fin_and_others_are_resets` — CLOSE 0x02 gives the guest a FIN; CLOSE 0x44 on another stream a RST and `last_close_reason == Some(0x44)`.
  - `packets_for_unknown_or_closed_streams_are_ignored` — DATA, CONTINUE and CLOSE for stream 999 and for a stream already closed: no panic, no guest frame, other streams unaffected.
  - `a_guest_close_after_a_server_close_sends_no_second_close`.
  - `losing_the_connection_resets_every_stream` — two established streams, `connection_lost`: two RSTs to the guest, state `Disconnected`, and after `connecting` + CONTINUE a new SYN gets a CONNECT with a fresh stream id.
  - `udp_datagrams_need_no_credit` — credit 0, a UDP datagram still goes out.
  - `info_packets_are_ignored` — a type 5 packet before CONTINUE changes nothing.
